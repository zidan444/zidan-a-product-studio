# Digital Canvas Studio

Build a premium, highly creative portfolio website for Zidan Ahammed, a Full-Stack Developer.

CORE DIRECTION

Do NOT create a conventional developer portfolio.

The website should feel like a high-end digital product / creative technology studio website, where the portfolio itself feels like a product.

The visual inspiration is the provided reference image: an immersive, editorial, image-driven website with minimal UI, strong typography, large visual areas, atmospheric transitions, and unconventional navigation.

IMPORTANT:

Do NOT copy the reference website.

Do NOT reproduce its exact layout, colors, typography, text, branding, or imagery.

Extract the design philosophy only.

Adapt that philosophy into a distinctive developer portfolio.

The final result must feel original.

The primary impression should be:

"This developer has real product experience and knows how to build creative digital experiences."

Secondary impression:

"This is much more interesting than a typical developer portfolio."

VISUAL IDENTITY

Direction:

Dark + experimental + cinematic + creative technology

Combine:

premium editorial design

modern digital-product aesthetics

subtle futuristic elements

strong typography

immersive visuals

large negative space

asymmetric layouts

controlled motion

sophisticated transitions

Avoid:

generic SaaS landing-page design

excessive rounded cards

generic glassmorphism everywhere

template-looking sections

stock developer illustrations

excessive gradients

standard skill percentage bars

generic "Hi, I'm a developer" hero

standard navigation bars

repetitive card grids

The design should feel intentionally art-directed.

COLOR SYSTEM

Use a dark base.

Suggested foundation:

near-black / charcoal background

off-white typography

muted gray secondary text

one sophisticated accent color

The accent can be a restrained electric green / acid green or another refined technology-inspired accent, but it must NOT look like a gaming website.

Use color sparingly.

The visual hierarchy should primarily come from:

typography

scale

spacing

composition

imagery

motion

rather than lots of colored components.

TYPOGRAPHY

Typography is one of the most important parts of the website.

Use a modern, premium sans-serif typeface.

Create strong contrast between:

enormous display typography

small uppercase metadata

restrained body text

Headlines should sometimes occupy a large portion of the viewport.

Use typography as part of the visual design, not simply as content.

Example characteristics:

Large:
ZIDAN AHAMMED

or

I BUILD DIGITAL PRODUCTS.

with supporting text appearing much smaller.

Do not make every heading huge. Create rhythm between large and small typography.

HERO / OPENING EXPERIENCE

The hero must NOT look like a normal developer portfolio.

No centered:

"Hi, I'm Zidan"

with two buttons underneath.

Instead, create an immersive opening viewport.

The first screen should establish:

ZIDAN AHAMMED

and a powerful statement about what I do.

Possible conceptual direction:

I BUILD DIGITAL PRODUCTS
THAT PEOPLE ACTUALLY USE.

or another stronger variation that communicates real product development.

Supporting metadata can communicate:

FULL-STACK DEVELOPER

REACT · NODE · ANGULAR · IONIC

But keep it visually secondary.

The hero should have a large atmospheric visual layer.

Since there is no personal photo, DO NOT create a fake portrait.

Instead use abstract/product-oriented visuals such as:

subtle technical textures

distorted interface fragments

oversized UI elements

abstract digital surfaces

blurred product screenshots

flowing grid structures

subtle code/interface motifs

The visual should feel like a digital environment rather than decorative stock art.

UNCONVENTIONAL NAVIGATION

Do NOT use the standard:

Home | About | Projects | Skills | Contact

navbar.

Create a more experimental navigation system.

Possible direction:

A small floating index / vertical navigation system that appears subtly at the edge of the viewport.

For example:

01 / INTRO
02 / WORK
03 / EXPERIENCE
04 / STACK
05 / CONTACT

The navigation should feel like part of the interface rather than a website menu.

On hover:

the section name becomes visible

a subtle indicator animates

active section is clearly identifiable

On mobile, transform this into a compact floating control rather than forcing a desktop navigation layout.

SCROLL EXPERIENCE

Scrolling should feel intentional.

Use moderate motion design:

smooth section transitions

text reveal animations

subtle image parallax

masked typography reveals

hover interactions

small displacement effects

elements entering the viewport with controlled motion

subtle scale transitions

Do NOT overanimate the website.

The goal is:

"This feels alive."

not:

"Look how many animations we added."

Respect prefers-reduced-motion.

Example concept:

Keep this section visually spacious.

Do not create a large biography.

Do NOT use a standard 3-column project-card grid.

Create an editorial project showcase.

Use large visual project presentations.

Each project should feel like a case study.

title responds to cursor

transition should feel premium

Clicking a project should open either:

a dedicated case-study page, OR

an immersive project overlay

Prefer dedicated case-study pages if Lovable can implement them cleanly.

SECTION 05 — HOW I WORK

Create a short section showing development mindset.

Possible structure:

02 — BUILD
Translate requirements into functional interfaces and systems.

03 — REFINE
Fix edge cases, responsiveness and interaction issues.

04 — SHIP
Build, test and deliver production-ready experiences.

Keep this section concise.

The purpose is to communicate that I am a product-minded developer, not someone who only writes code.

FOOTER

Keep it extremely minimal.

Example information:

FULL-STACK DEVELOPER

Current year.

No unnecessary footer menus.

RESPONSIVENESS

This is critical.

The website must be fully responsive across:

large desktop

laptop

tablet

mobile

Do NOT simply shrink the desktop layout.

The composition should be intentionally redesigned for mobile.

On mobile:

typography must remain visually impressive

no horizontal overflow

navigation becomes compact

project imagery remains prominent

animations remain smooth but lighter

touch interactions must work

buttons must have proper touch targets

text must never overlap important visuals

Test every section at approximately:

1440px

1280px

1024px

768px

430px

390px

375px

ACCESSIBILITY & PERFORMANCE

Implement:

semantic HTML

keyboard navigation

visible focus states

sufficient text contrast

alt text for project images

prefers-reduced-motion

optimized image loading

lazy loading for non-critical images

no unnecessary animation libraries if CSS can handle the effect

avoid excessive JavaScript animation loops

The website must feel premium without becoming slow.

TECHNICAL IMPLEMENTATION

Use a clean modern React architecture.

Prefer:

React

TypeScript

Tailwind CSS

reusable components

clean component hierarchy

Create reusable components for:

navigation

project showcase

project metadata

section headings

animated text

buttons

footer

Keep the code maintainable.

Do not put the entire website into one giant component.

IMPORTANT DESIGN RULE

The portfolio should NOT scream:

"I used React to build a portfolio."

It should communicate:

"I am a developer who understands products, interfaces, systems and user experience."

The design itself should be evidence of that.

FINAL QUALITY BAR

Before considering the website complete, review it critically.

Ask:

Does it look like a generic developer template?
→ If yes, redesign it.

Does the GScope professional experience immediately stand out?
→ If no, improve hierarchy.

Does the first screen make someone want to scroll?
→ If no, redesign the hero.

Is the navigation visually distinctive?
→ If it looks like every portfolio navbar, replace it.

Is there too much text?
→ Remove it.

Are there too many cards?
→ Remove them.

Are animations distracting?
→ Reduce them.

Does the site still look professional enough for recruiters?
→ If no, simplify.

Does it communicate both real product experience and creative developer identity?
→ This is the final success criterion.

The finished result should feel like a creative technology portfolio / digital product experience, not a resume converted into a website.
